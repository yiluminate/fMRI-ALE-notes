# Organizing Analysis Results

[Home](../README.md) · [Run record template](../templates/run-record.md) · [Reporting outline](../templates/reporting-outline.md)

Preserve the relationships among each analysis’s inputs, parameters, outputs, figures, tables, and interpretation.

## Organize Files by Run ID

Use separate analysis identifiers, such as `run-001/` and `run-002/`, to retain:

- A completed [run record](../templates/run-record.md) for that analysis.
- Frozen inputs and the locations of the corresponding source, grouping, and transformation records.
- Statistical images, final thresholded maps, cluster/peak tables, and logs actually generated by the software.
- Exported figures, legends, and display settings.
- Explanations of warnings, the absence of significant clusters, failures, or changes to the analysis plan.

Generally retain the software’s original output filenames and identify their types and directions in the output table. Store analyses with different spaces or parameters separately.

## Output Inventory Fields

| Run ID | Filename | Image/table/log type | Dataset and direction | Threshold and correction status | Subsequent use |
| --- | --- | --- | --- | --- | --- |
| To be completed | To be completed | To be completed | To be completed | To be completed | To be completed |

Identify A, B, pooled, conjunction, A > B, and B > A separately. The statistical meaning of an image cannot be established solely from `.nii`, `pID`, `clust`, or its colors.

## Distinguish a Completed Analysis with No Surviving Clusters from a Failed Run

If computation finishes but no clusters survive the prespecified thresholds, record the actual thresholds and output status. Describe errors, incomplete runs, and missing outputs separately. Keep statistical results distinct from display-range adjustments.
